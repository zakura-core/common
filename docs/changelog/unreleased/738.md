## zakura-sapling-crypto

### Changed

- Changed `SpendDescription::rk` to return the key's unvalidated
  `redjubjub::VerificationKeyBytes`. Decode it with
  `redjubjub::VerificationKey::try_from` before using it as a key.
  `SpendDescription::from_parts` and `SpendDescriptionV5::from_parts` accept
  either the bytes or a decoded key
  ([#738](https://github.com/zakura-core/common/pull/738)).
- Changed `BatchValidator::check_bundle` to reject a spend whose `rk` is not a
  canonical Jubjub point encoding, a check that transaction parsing used to
  make ([#738](https://github.com/zakura-core/common/pull/738)).

## zakura-primitives

### Changed

- Changed transaction parsing to keep each Sapling spend's `rk` as bytes
  without decoding it, which avoids a field square root per spend. Parsing no
  longer rejects an invalid `rk` encoding; Sapling verification rejects it
  instead ([#738](https://github.com/zakura-core/common/pull/738)).
