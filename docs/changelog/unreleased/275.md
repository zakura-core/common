## zakura-pasta-curves

### Changed

- Private multicore prepared evaluations on AArch64 macOS now use
  alpha-eight for the measured 2,048-term SRS tier, trading about 12.4 MiB of
  additional retained memory per table for lower repeated-evaluation latency.
  All other inputs and the public `orbits` planner retain the existing 13 MiB
  planning policy
  ([#275](https://github.com/zakura-core/common/pull/275)).

## zakura-halo2-proofs

### Changed

- On AArch64 macOS, no-orbits prepared commitments for a `k = 11` Pasta SRS
  now retain about 50.1 MiB across the coefficient, Lagrange, and blind tables
  to reduce repeated commitment latency. Explicit preparation takes about
  30.0 ms longer on the measured Apple M4; other targets retain the previous
  approximately 25.3 MiB preparation
  ([#275](https://github.com/zakura-core/common/pull/275)).

## zakura-orchard

### Changed

- On AArch64 macOS when built without the `orbits` feature,
  `ProvingKey::prepare_proving` now uses the wider alpha-eight tables,
  increasing retained preparation from about 25.3 MiB to 50.1 MiB. Across
  100 balanced pairs with ten workers on Apple M4, this reduced one-Action
  proof latency by 0.472 ms (95% CI 0.299--0.646 ms) and four-Action latency
  by 0.987 ms (95% CI 0.678--1.290 ms), while adding about 30.0 ms to explicit
  preparation
  ([#275](https://github.com/zakura-core/common/pull/275)).
