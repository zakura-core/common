## zakura-transparent

### Added

- Added opt-in SLH-DSA-SHA2-128f and SLH-DSA-SHA2-192s key generation, signing,
  and verification through the `pq` feature, behind a versioned transparent output
  type. The output carries the version, so validation can classify an output when
  it is created rather than when it is spent, and reject a malformed or
  unknown-version one while the sender still holds the coins. The version selects
  the parameter set, the signing context and the commitment, which remains a
  HASH160 hash of the committed script for now and appears only in the output.
  Spends authenticate that commitment, require a canonical serialized input, and
  share existing script operations and multisig rules. These APIs cover PQ outputs
  only, so every other output keeps the evaluator and flags it uses today. Callers
  supply a trusted previous output and transaction checker; these APIs do not
  activate PQ outputs
  ([#650](https://github.com/zakura-core/common/pull/650)).

## zakura-zcash-script

### Added

- Added a raw-signature checking hook that preserves ECDSA behavior by default,
  and an opt-in `pq` evaluator with bounds for larger serialized arguments and
  stack payloads. The PQ evaluator additionally requires minimally encoded input
  pushes and a single final stack item, neither of which the legacy evaluator
  enforces ([#650](https://github.com/zakura-core/common/pull/650)).

## zakura-primitives

### Added

- Added a `pq` feature that enables the transparent PQ signature and script APIs
  ([#650](https://github.com/zakura-core/common/pull/650)).
