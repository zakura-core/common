## zakura-primitives

### Added

- Added `TransactionData::check_v7_transaction_rules` and the non-exhaustive
  `v7::TransactionRuleError`. The check covers the ZIP 248 value and input
  and output rules that one v7 transaction decides by itself: the fee delta
  is not negative in a coinbase transaction and not positive otherwise, the
  value pool deltas sum to zero, the transaction has an input and an output,
  the Orchard pool balance is not negative, the transparent delta is at
  least the negated total of the transparent outputs and equal to it without
  transparent inputs, and a coinbase transaction expires at its block height
  and has a coinbase delta equal to the block subsidy less the lockbox
  deposit and the ZIP 235 fee contribution, which is 60% of its fee delta,
  rounded down. It does not verify proofs or signatures, or any rule on the
  contents of a shielded bundle. Decoding does not run it, because a
  transaction that breaks one of these rules is well-formed. Full validators
  still check the rules that need the block or the spent outputs
  ([#757](https://github.com/zakura-core/common/pull/757)).

### Changed

- Decoding a v7 transaction into `TransactionData` now rejects a value pool
  delta for the ZIP 233 bundle with the new
  `v7::BundleRuleError::InactiveBundle`, on the assumption that NU7.1 does
  not activate that bundle. `v7::ValueDeltas` no longer has the `nsm` field,
  so typed v7 data cannot carry that delta. `v7::Envelope` still parses and
  identifies such a transaction
  ([#757](https://github.com/zakura-core/common/pull/757)).
