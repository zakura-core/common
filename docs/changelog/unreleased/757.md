## zakura-primitives

### Added

- Added `TransactionData::check_v7_transaction_rules` and the non-exhaustive
  `v7::TransactionRuleError`. The check covers the consensus rules that one
  v7 transaction decides by itself: the fee delta is not negative in a
  coinbase transaction and not positive otherwise, the value pool deltas sum
  to zero, the transaction has an input and an output, the Orchard pool
  balance is not negative, the transparent delta of a transaction without
  transparent inputs is the negated total of its outputs, and a coinbase
  transaction expires at its block height and has a coinbase delta equal to
  the block subsidy less the lockbox deposit and a fee contribution between
  zero and the collected fees. Decoding does not run it, because a
  transaction that breaks one of these rules is well-formed. Full validators
  still check the rules that need the block or the spent outputs
  ([#757](https://github.com/zakura-core/common/pull/757)).

### Changed

- Decoding a v7 transaction into `TransactionData` now rejects a value pool
  delta for the ZIP 233 bundle, which no consensus branch activates, with the
  new `v7::BundleRuleError::InactiveBundle`. `v7::ValueDeltas` no longer has
  the `nsm` field, so typed v7 data cannot carry that delta. `v7::Envelope`
  still parses and identifies such a transaction
  ([#757](https://github.com/zakura-core/common/pull/757)).
