## zakura-pasta-curves

### Changed

- Private multicore prepared evaluations on AArch64 macOS now use
  alpha-eight for the measured 2,048-term SRS tier, trading 12,978,176 bytes
  (about 12.4 MiB) of additional retained memory per table for lower
  repeated-evaluation latency.
  All other inputs and the public `orbits` planner retain the existing 13 MiB
  planning policy
  ([#338](https://github.com/zakura-core/common/pull/338)).

## zakura-halo2-proofs

### Changed

- On AArch64 macOS, no-orbits prepared commitments for a `k = 11` Pasta SRS
  now retain 52,436,992 accounted bytes (about 50.0 MiB) across the
  coefficient, Lagrange, and fixed-generator tables, up from 26,480,640 bytes
  (about 25.3 MiB). Explicit preparation takes about 15.5 ms longer on the
  measured Apple M4; other targets retain the previous preparation
  ([#338](https://github.com/zakura-core/common/pull/338)).

## zakura-orchard

### Changed

- On AArch64 macOS when built without the `orbits` feature,
  `ProvingKey::prepare_proving` now uses the wider alpha-eight tables,
  increasing the dominant accounted preparation from about 25.3 MiB to
  50.0 MiB. Across
  100 balanced pairs with ten workers on Apple M4, this reduced one-Action
  proof latency by 0.644 ms (95% CI 0.497--0.792 ms) and four-Action latency
  by 1.007 ms (95% CI 0.638--1.377 ms), while adding about 15.5 ms to explicit
  preparation
  ([#338](https://github.com/zakura-core/common/pull/338)).
