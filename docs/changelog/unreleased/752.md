## zakura-orchard

### Added

- Added `bundle::TxVersion::V7` and its Orchard and Ironwood commitment formats
  for ZIP 248 v7 transactions. Their effects digests commit to the flags but
  not to the value balance, and their authorizing digests commit to the anchor
  first and include each signature's `sighashInfo`
  (`bundle::commitments::V7_SIGHASH_INFO_V0`). `hash_bundle_txid_empty` and
  `hash_bundle_auth_empty` return `CommitmentError::InvalidTransactionVersion`
  for v7, which omits absent bundles from its digests
  ([#752](https://github.com/zakura-core/common/pull/752)).
- Added `bundle::commitments::hash_v7_bundle_effects` and
  `bundle::commitments::hash_v7_bundle_auth`, with
  `bundle::commitments::V7SignatureField`, which compute the v7 effects and
  authorizing digests of an Orchard or Ironwood bundle from its encoded fields,
  without a `Bundle`. They compute the same digests as `Bundle::commitment`
  and `Bundle::authorizing_commitment` for v7, hash the flag byte and each
  `sighashInfo` as given, and need no bundle version
  ([#752](https://github.com/zakura-core/common/pull/752)).

## zakura-primitives

### Added

- Added `TxVersion::V7`, the ZIP 248 v7 transaction format, which is valid
  only under `BranchId::Nu7_1`. `Transaction::read`, `Transaction::write`, the
  transaction identifier, the authorizing data commitment, and `Block::read`
  support it. `TxVersion` is exhaustive, so the new variant breaks exhaustive
  matches ([#752](https://github.com/zakura-core/common/pull/752)).
- Added `TransactionData::from_parts_v7`, `TransactionData::v7_fields`,
  `TransactionData::coinbase_bundle`, `TransactionData::value_pool_deltas`, and
  `TransactionData::is_coinbase`, with the types `v7::V7Fields`,
  `v7::ValueDeltas`, `v7::CoinbaseBundle`, `v7::MinerPoll`, `v7::MinerSignal`,
  `v7::CoinbaseError`, `v7::BundleRuleError`, `v7::MAX_COINBASE_DATA_LEN`, and
  `v7::SIGHASH_INFO_V0`. `V7Fields`, `ValueDeltas`, `CoinbaseError`, and
  `BundleRuleError` are non-exhaustive while ZIP 248 is a draft, so
  `V7Fields` and `ValueDeltas` are built from their `Default` values.
  `from_parts_v7` returns a `v7::BundleRuleError` for parts that break a
  ZIP 248 bundle-local rule, specify an unsupported branch, or set an expiry
  height above 499,999,999.
  Rejected bundles include Sapling spends with different anchors, a transparent or coinbase value pool delta without
  its bundle, a coinbase transaction with transparent inputs, Sapling spends,
  or Orchard or Ironwood spends enabled, or an Orchard or Ironwood bundle whose
  version is not that of its pool in the transaction's consensus branch.
  `TransactionData::freeze` checks the same rules again for v7 data, whose
  bundles `map_bundles` and `try_map_bundles` can replace. The rule that
  transparent signatures use `SIGHASH_ALL` is checked by script verification
  under `zcash_script`'s `Flags::SigHashAllOnly` instead. Decoding a v7
  transaction into `TransactionData` enforces the same rules, and rejects
  bundles that are not registered or that the registry does not permit in
  their map, missing authorizing data, and signatures that do not use sighash
  variant 0; `v7::Envelope` still parses such transactions. Full validators
  still check the rules that relate the values of bundles to each other or to
  the chain, such as the balance of the value pool deltas and the sign of the
  fee ([#752](https://github.com/zakura-core/common/pull/752)).
- Added `sighash::V7SignatureHashes` to prepare the transaction ID and previous-output
  commitments once when computing multiple v7 signature hashes.
- Added the ZIP 248 sighash variant 0 signature digest:
  `sighash::SignableInput::V7Shielded`, `v7::ShieldedBundleType`,
  `v7::ShieldedSignature`, and `sighash::SighashError`. `SignableInput` is
  exhaustive, so the new variant breaks exhaustive matches; `SighashError` is
  non-exhaustive ([#752](https://github.com/zakura-core/common/pull/752)).
- Added `v7::Envelope::txid` and `v7::Envelope::auth_digest`, which compute
  the digest of each bundle whose pair the registry gives an encoding in that
  map from its payloads alone, and take from the caller, through a
  `Fn(BundleId) -> Option<[u8; 32]>`, the digests of the others. The
  identifier reads only the effecting payloads, and the authorizing digest
  each authorizing payload with its effecting payload, which gives its counts.
  Unlike `Transaction::read`, neither needs a known consensus branch, the
  authorizing data, sighash variant 0, or the bundle-local rules that relate
  bundles; each `sighashInfo` is hashed as its field encoding. The payloads
  are decoded with the typed field decoders, so they must still pass checks
  beyond the ZIP 248 parsing rules that only consensus-invalid transactions
  fail: transparent output values at most `MAX_MONEY`, canonical
  Sapling `cmu`, `rk` and anchor, and canonical Orchard and Ironwood
  `nullifier`, `cmx`, `cv`, `rk` and anchor. They return the new
  `v7::DigestError`: `MissingDigest` if a needed digest is not supplied, and
  `InvalidPayload`, naming the bundle and map, if a registered payload does
  not decode
  ([#752](https://github.com/zakura-core/common/pull/752)).
- Added `TxDigests::v7_digests` and the non-exhaustive `V7TxIdDigests`. The
  new public field breaks `TxDigests` struct literals
  ([#752](https://github.com/zakura-core/common/pull/752)).

### Changed

- At NU7.1 the standard wallet builder selects v5 for a transaction that can use
  it and v6 when Ironwood is required. Explicit version requests are preserved.
- Renamed `v7::Envelope::txid` and `v7::Envelope::auth_digest`, which take
  the digest of every bundle from the caller and so identify any well-formed
  envelope, to `txid_with_bundle_digests` and `auth_digest_with_bundle_digests`
  ([#752](https://github.com/zakura-core/common/pull/752)).
- Changed `sighash::signature_hash` to return
  `Result<SignatureHash, SighashError>`. It rejects a v7 transparent signature
  that does not use `SIGHASH_ALL`, a signer that belongs to another
  transaction version, and spent outputs that do not match the transparent
  inputs ([#752](https://github.com/zakura-core/common/pull/752)).
- Changed `TransactionData::from_parts` to panic for `TxVersion::V7`, whose
  data is constructed with `from_parts_v7`
  ([#752](https://github.com/zakura-core/common/pull/752)).
- Changed `TransactionDigest`: `digest_transparent` and `digest_ironwood` take
  the transaction version, `combine` takes the digest of the v7-only parts,
  and implementations provide `V7Digest` and `digest_v7`. The bundle digests
  of `BlockTxCommitmentDigester` are now `None` for a bundle without
  authorizing data ([#752](https://github.com/zakura-core/common/pull/752)).
- Changed `TransactionData::fee_paid` to return the explicit fee of a v7
  transaction without looking up previous outputs, and zero for a v7 coinbase
  transaction ([#752](https://github.com/zakura-core/common/pull/752)).
- Changed `txid::to_txid` to support `TxVersion::V7`. It panics for v7
  digests that lack `TxDigests::v7_digests`, which `txid::TxIdDigester`
  computes for every v7 transaction
  ([#752](https://github.com/zakura-core/common/pull/752)).
- Documented that `sighash_v4::v4_signature_hash` panics for a
  `SignableInput::V7Shielded` signature, which exists only in v7 transactions;
  `sighash::signature_hash` returns `SighashError::SignerVersionMismatch` for
  it instead ([#752](https://github.com/zakura-core/common/pull/752)).

### Removed

- Removed the public `sighash_v5` and `sighash_v6` modules. Use
  `sighash::signature_hash`, which computes the same digests and rejects the
  signers of other transaction versions
  ([#752](https://github.com/zakura-core/common/pull/752)).

## zakura-zcash-script

### Added

- Added `interpreter::Flags::SigHashAllOnly` and `interpreter::Error::SigHashNotAll`.
  Under the flag, every nonempty signature passed to `OP_CHECKSIG`,
  `OP_CHECKSIGVERIFY`, `OP_CHECKMULTISIG`, or `OP_CHECKMULTISIGVERIFY` must use
  `SIGHASH_ALL`, including signatures the operation does not go on to check.
  This is the ZIP 248 rule for transparent inputs signed with sighash
  variant 0. `Error` is exhaustive, so the new variant breaks exhaustive
  matches ([#752](https://github.com/zakura-core/common/pull/752)).
