## zakura-halo2-proofs

### Changed

- Materialized structurally identified 10-bit lookup inputs directly from
  their histograms, and moved validation of Orchard's canonical fixed 10-bit
  table into key generation. This removes 130,688 bytes of logical traffic per
  Action and 196,032 action-neutral bytes per proof, while avoiding 2,042
  canonical field encodings and histogram increments per proof. Focused Apple
  M4 kernels saved about 0.38 us per input and 10.5--10.7 us per fixed table;
  paired macOS and Linux cold-proof screens were neutral. The proving key
  retains only 34 logical bytes of markers for Orchard, while the existing
  transient 2 KiB histogram and large allocation shape are unchanged. Proof
  bytes, the proof system, and public APIs are unchanged
  ([#448](https://github.com/zakura-core/common/pull/448)).
