## zakura-protocol

### Added

- Added `NetworkUpgrade::Nu7_1` and `BranchId::Nu7_1`, the upgrade that is
  expected to deploy the ZIP 248 v7 transaction format. It has no Mainnet or
  Testnet activation height, and its branch ID `0xfffffffe` is a placeholder
  until a deployment ZIP assigns one. Both enums are exhaustive, so the new
  variants break downstream exhaustive matches
  ([#248001](https://github.com/zakura-core/common/pull/248001)).
- Added `LocalNetwork::nu7_1`, which is a breaking change for code that builds
  `LocalNetwork` with a struct literal
  ([#248001](https://github.com/zakura-core/common/pull/248001)).
- Added `constants::V7_TX_VERSION` and `constants::V7_VERSION_GROUP_ID`. ZIP 248
  has not assigned the version group ID, so `0xFFFFFFF7` is a placeholder
  ([#248001](https://github.com/zakura-core/common/pull/248001)).

## zakura-primitives

### Added

- Added `transaction::v7`, the bundle-agnostic layer of the ZIP 248 v7
  transaction format: the bundle registry (`BundleType`, `BundleVariant`,
  `BundleId`, `Registration`), and the `Envelope` encoding with opaque bundle
  payloads, the ZIP 248 parsing rules, and a nonzero consensus branch ID
  (`EnvelopeError`). `Registration` and `EnvelopeError` are non-exhaustive,
  since the registry and the rules may grow while ZIP 248 is a draft.
  `Envelope::txid` and `Envelope::auth_digest` compute the transaction
  identifier and authorizing data commitment from per-bundle digests, which a
  caller can supply for bundles it does not understand
  ([#248001](https://github.com/zakura-core/common/pull/248001)).

### Changed

- Changed `TxVersion::valid_in_branch` and `TxVersion::suggested_for_branch` to
  treat `BranchId::Nu7_1` like `BranchId::Nu7`
  ([#248001](https://github.com/zakura-core/common/pull/248001)).
