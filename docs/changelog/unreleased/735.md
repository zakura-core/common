## zakura-sensei

### Added

- Added `configure_workers` and `worker_budget`, with `WorkersConfigError`,
  to bound the process-wide worker pool shared by proving, verification, and
  pooled RedPallas batch verification before it initializes
  ([#735](https://github.com/zakura-core/common/pull/735)).
- Added `warm_up_verifier_scratch`, which provisions the verifier's bounded
  idle scratch pools for an expected batch shape and returns a
  `VerificationPlan` (the provisioned scratch bytes, the concurrent batches
  served without allocating a final-MSM workspace, and the idle-memory bound)
  for sizing admission control
  ([#735](https://github.com/zakura-core/common/pull/735)).

### Changed

- Changed the worker pool's default size: unless `configure_workers` sets it,
  a positive `RAYON_NUM_THREADS` now sizes the pool, ahead of the detected
  parallelism. A process that exports the variable for its own Rayon pools
  now gets a Sensei pool of that size as well
  ([#735](https://github.com/zakura-core/common/pull/735)).
- Batch verification now reuses per-chunk equation scratch and the final-MSM
  workspace from bounded idle pools whose slot counts follow the worker
  budget, returning them after success and reported errors alike, so repeated
  concurrent verification has predictable retained memory (eight concurrent
  64-proof batches on a 32-thread Intel host peak at 321 MB of resident
  memory instead of 987 MB) ([#735](https://github.com/zakura-core/common/pull/735)).
- Verification parallelism now follows the work: folding cuts at most one
  chunk per two Actions and runs single-chunk batches on the calling thread,
  the final MSM requests one task per 128 terms, and the batch's transcript
  points enter the final MSM as slices of at least 1,024 points, so a
  one-bundle batch no longer fans out across the whole pool and a 64-bundle
  batch verifies in 7.2 ms at 32 workers on a 16-core Intel host (8.6 ms
  before, 7.9 ms for the Halo2 backend)
  ([#735](https://github.com/zakura-core/common/pull/735)).

## zakura-orchard

### Added

- Added the `batch_validation` benchmark target, which measures isolated,
  concurrent, and cold `BatchValidator` latency over a corpus of two-Action
  payments for whichever proof backend is compiled in
  ([#735](https://github.com/zakura-core/common/pull/735)).
