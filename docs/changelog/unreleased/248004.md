## zakura-transparent

### Added

- Added `builder::TransparentBuilder::build_v7_coinbase`, which builds the
  outputs-only transparent bundle of a ZIP 248 v7 coinbase transaction
  ([#248004](https://github.com/zakura-core/common/pull/248004)).

## zakura-primitives

### Added

- Added ZIP 248 v7 transaction construction to `builder::Builder`. A standard
  transaction is built as v7 after `Builder::propose_version(TxVersion::V7)`,
  which is valid from NU7.1; its fee is stated in the fee bundle, and each
  Sapling, Orchard, and Ironwood signature signs its own digest
  ([#248004](https://github.com/zakura-core/common/pull/248004)).
- Added `builder::BuildConfig::V7Coinbase` and `builder::V7CoinbaseConfig` for
  building a v7 coinbase transaction. The builder derives its coinbase bundle
  and value pool deltas from the block subsidy, lockbox deposit, fees, and
  ZIP 235 fee contribution, and requires the outputs to pay exactly the
  subsidy less the lockbox deposit, plus the fees less the ZIP 235
  contribution. `BuildConfig` is exhaustive, so the new variant breaks
  exhaustive matches ([#248004](https://github.com/zakura-core/common/pull/248004)).
- Added the `builder::Error` variants `CoinbaseVersionMismatch`,
  `InvalidExpiryHeight`, `V7Coinbase`, `NsmFeeContributionExceedsFees`,
  `Sighash`, and `PcztUnsupported`. `InvalidExpiryHeight` rejects a v7
  transaction whose expiry height is above ZIP 203's limit of 499999999.
  `Error` is exhaustive, so they break exhaustive matches
  ([#248004](https://github.com/zakura-core/common/pull/248004)).

### Changed

- Changed `Builder::build_for_pczt` to return `Error::PcztUnsupported` for a
  v7 transaction, which PCZTs cannot represent yet
  ([#248004](https://github.com/zakura-core/common/pull/248004)).
